# NF-23 · Пост-рейс розбір: спліти проти плану, крива темпу, дрейф пульсу

**Тип:** нова фіча (аудит коду 2026-08-05, кат. C) · **Оцінка:** M ·
**Пріоритет:** 🟠 high (замикає єдину петлю, яка досі рветься) · **Поверхня:** бот + веб ·
**Залежності:** EP-05 ✅ (race pack), NF-22 ✅ (race week), NF-17 ✅ (цільовий час),
EP-15 ✅ (GAP), NF-14 ✅ (`fetch_activity_splits`)

## Проблема

Продукт веде користувача до старту (pack на T-7, чекліст T-3, бріф T-1) — і замовкає
рівно тоді, коли з'являються найцінніші дані сезону. Забіг падає в `activities` як
звичайна пробіжка: авто-аналіз `/activity` не знає, що це був старт, не знає цільового
темпу з pack, не порівнює спліти з планом розкладки і не дає висновку на наступний цикл.
Розбір, що склався у голові за тиждень після старту, ніде не фіксується — і наступна
підготовка починається з нуля.

У §5 BA-аудиту 2026-07-23 фіча свідомо відкладена як «кандидат наступної партії після
NF-22». NF-22 закрито 2026-08-04 — блокер знято.

## User story

Як бігун я хочу наступного дня після старту отримати розбір: де я біг швидше/повільніше
за цільову розкладку, скільки втратив на другій половині, як поводився пульс — і що з
цього змінити в наступному циклі, щоб досвід старту не випарувався.

## Обсяг

**Входить:**

1. **Позначка старту.** `PlannedWorkout` цілі (`type="race"` або дата == `target_date`
   активного плану) матчиться з активністю наявним EP-01-матчером; додатково — ручне
   `/race done <activity_id>` на випадок, коли плану немає.
2. **Чистий модуль `app/postrace.py`** (нуль мережі, нуль LLM) поверх
   `fetch_activity_splits` + `series`:
   - крива темпу по кілометрах, GAP-нормалізована (`app.gap`);
   - **positive/negative split** — Δ% друга половина проти першої;
   - **fade point** — перший кілометр, після якого темп не повертається в коридор;
   - **дрейф пульсу** (decoupling) — pace:HR перша vs друга половина (`app.efficiency`
     уже має розрахунок EF, реюз);
   - порівняння з цільовою розкладкою: цільовий темп бере з `TrainingPlan.intake`
     (NF-17 `target_time`) або з збереженого pack; без цілі — секція просто відсутня.
3. **Наратив** — один Claude-виклик (Sonnet, `kind="race_debrief"`), контекст: числа з
   п.2 + погода дня старту + тижні підготовки (обсяг/виконаність за EP-01) + RPE/біль з
   `subjective`. Промпт-фокус: **3 висновки на наступний цикл**, не переказ цифр.
4. **Доставка:** DM наступного ранку (гілка в `plan_sync_job`, guard
   `race_debrief_sent:<plan_id>`) + секція на `/plan/{id}` архівного плану — щоб через
   рік розбір читався поруч із планом, який до нього привів.

**Не входить:** порівняння з іншими стартами (це NF-06 `/compare`, окремо), автоматична
генерація наступного плану з висновків (окремий крок — юзер тисне «новий план» сам).

## Acceptance criteria

- [ ] Забіг без спліт-даних (вимкнено авто-лап) → розбір деградує до series-кривої, не
      падає; зовсім без series → лише агрегати + наратив.
- [ ] Positive/negative split і fade point рахуються на GAP-темпі, не на сирому (тікет
      марний на горбистій трасі інакше) — тест на синтетичному профілі з підйомом.
- [ ] Немає цілі часу → секція «проти розкладки» відсутня, решта є.
- [ ] Рівно один Claude-виклик на старт; повтор `/race done` того самого id → кеш-хіт
      (`kind` + `activity_id` у ключі дедуп-кеша — див. «наскрізну пастку»).
- [ ] Guard: розбір шлеться раз; архівація плану знімає невідправлений.
- [ ] Тести: `tests/test_postrace.py` — чистий модуль (спліти/fade/decoupling), гілка
      джоби, деградації.

## Технічні дотики

`app/postrace.py` (новий), `app/garmin/client.py::fetch_activity_splits` (реюз),
`app/gap.py`, `app/efficiency.py`, `app/analysis/reports.py` (+`run_race_debrief`),
`app/analysis/prompts.py` (`SYSTEM_RACE_DEBRIEF`), `bot/jobs.py::_race_pack_for_user`
(нова стадія T+1), `bot/handlers.py::race_cmd` (підкоманда `done`),
`app/routers/plan.py` (секція на архівному плані).

## Вартість LLM / запити до Garmin

LLM: +1 Sonnet-виклик на старт (1–3 рази/рік) ≈ $0.02. Garmin: 0 нових (спліти й series
вже тягнуться авто-аналізом). Open-Meteo: 0 (погода дня старту вже в історії).

## Ризики

- Цільовий темп із текстового pack парситься крихко → та сама рекомендація, що в NF-22:
  зберігати структуровану вижимку pack у `bot_state` при генерації.
- «Старт» помилково розпізнаний на звичайній пробіжці → тільки явний `type="race"`/
  `target_date`/ручна команда, ніякої евристики «швидко і довго».

## RICE

Reach 0.2/міс · Impact 3 · Confidence 0.9 · Effort ~4 дні → **Score ≈ 0.14** (низький
Reach обманює: це пік цінності за рік, і без нього петля «підготовка → старт → висновки»
не замикається).
