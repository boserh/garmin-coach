# UI-05 · Сторінка «Інсайти»: усе, що вже пораховано, але видно лише в Telegram

**Тип:** нова фіча (UI-аудит 2026-08-06) · **Оцінка:** M ·
**Пріоритет:** 🔴 highest · **Поверхня:** веб ·
**Залежності:** NF-02 ✅, NF-04 ✅, NF-07 ✅, NF-06 ✅, NF-11 ✅, NF-20 ✅, NF-23 ✅, NF-30 ✅

## Проблема

У `app/` лежить десяток **чистих детермінованих модулів**, кожен зі своїм готовим API — і
жоден із них не має веб-поверхні. Перевірено grep'ом по `app/routers` + `app/templates`:

| Модуль | Що вміє | Веб |
| --- | --- | --- |
| `correlations.py` (NF-02) | `find_correlations` — лагові кореляції метрик і lifestyle-тегів | **0 згадок** |
| `injury.py` (NF-04) | `assess` → `Assessment` зі списком `Signal` і рівнем | **0 згадок** |
| `wrapped.py` (NF-07) | квартальний/річний рекап зі статистикою і рекордами | лише в тексті `/info` |
| `fueling.py` (NF-11) | `advise` — вода/вуглеводи/сіль за тривалістю й спекою | **0 згадок** |
| `loadforecast.py` (NF-20) | `forecast_week` — ACWR-траса вперед | лише один рядок на дашборді |
| `postrace.py` (NF-23) | `build_debrief` — GAP-крива по км, спліт, точка згасання, decoupling | **0 згадок** |
| `returntorun.py` (NF-30) | стан драбини «ходьба/біг» після болю | **0 згадок** |
| `compare.py` (NF-06) | порівняння з минулим собою | лише службово в `/me` |

Усе це рахується **безкоштовно з БД** (0 викликів Claude, 0 запитів до Garmin) і
видається користувачеві **тільки як абзац тексту в Telegram**, який неможливо ані
переглянути пізніше, ані порівняти, ані показати лікарю/тренеру. Найдорожча частина
кодової бази має найгіршу поверхню.

## User story

Як користувач я хочу мати одну веб-сторінку, де видно, **чому** тренер каже те, що каже:
які сигнали ризику активні зараз, які кореляції він знайшов у моїй історії, куди йде
навантаження на цей тиждень — і все це переглядати коли завгодно, а не шукати в чаті.

## Обсяг

**Входить:**

1. **`GET /insights`** — серверний рендер, секції показуються лише за наявності сигналу
   (`has_signal`-функції вже є в `compare.py`/`wrapped.py`, для решти — перевірка на
   `None`, яку модулі вже чесно повертають):
   - **Ризик зараз** (NF-04): рівень + перелік `Signal` з їхніми поясненнями як картки,
     кожна з підсвіченим внеском — це наочна відповідь «чому радар мовчить/кричить»;
   - **Навантаження вперед** (NF-20): ACWR-траса графіком, а не одним числом;
   - **Кореляції** (NF-02): «сон 7+ год → HRV наступного дня +6%», зі значенням `n` і
     явною міткою, що це кореляція, не причина;
   - **Рекап** (NF-07) і **порівняння з минулим собою** (NF-06) — картками з
     перемикачем періоду;
   - **Активна драбина повернення** (NF-30), якщо йде.
2. **Розбір старту (NF-23) на сторінці активності** — `build_debrief` уже рахує криву по
   км, спліт половин, точку згасання і decoupling; показати кривою + двома цифрами, а не
   абзацом.
3. **Fueling (NF-11) у картці найближчого тренування** — `advise` дає готовий план води/
   вуглеводів; рядок на `/plan` і `/dashboard` для сесій, що проходять поріг тривалості.
4. **Посилання «звідки це» біля кожного блоку** — на `/me/...` з даними, на яких він
   порахований (прозорість, той самий принцип, що в EP-18-профілі з evidence-лінками).

**Не входить:** нові розрахунки й нові пороги — сторінка **тільки відображає** те, що
модулі вже повертають; будь-яка зміна логіки — окремий тікет. Жодних LLM-переказів
цифр — текст беруть із наявних `summary()`.

## Acceptance criteria

- [ ] **Нуль викликів Claude** на всьому шляху сторінки — тест з `assert` на відсутність
      виклику клієнта (той самий патерн, що в NF-29).
- [ ] Нуль запитів до Garmin — усе з БД (тест із замоканим провайдером, який падає при
      будь-якому виклику).
- [ ] Порожній акаунт (нема історії) → сторінка не падає й не показує порожніх секцій,
      а дає чесне «замало даних, потрібно N днів» з наявних гардів
      (`INJURY_MIN_HISTORY_DAYS` тощо), не вигаданих.
- [ ] Пороги не продубльовані: тест імпортує константи з модулів і перевіряє, що шаблон
      не містить власних чисел.
- [ ] Кореляції підписані як кореляції (є явний дисклеймер у розмітці) — цей блок
      найлегше прочитати як причинність.
- [ ] Мобільна розкладка на 320px (сторінка додана в `tests/test_mobile_layout.py`).

## Ризики

- Сторінка-звалище: шість блоків без ієрархії. Мітигація — жорсткий порядок «що робити
  зараз → що попереду → що я помітив за історією», і блок ховається, коли сигналу нема.
- Спокуса «хай Claude це перекаже гарніше» → окремий платний шлях; AC про нуль викликів
  стоїть саме проти цього.
