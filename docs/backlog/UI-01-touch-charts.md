# UI-01 · Графіки, які працюють пальцем (і один компонент замість чотирьох копій)

**Тип:** сторі покращення (UI-аудит 2026-08-06) · **Оцінка:** S ·
**Пріоритет:** 🔴 highest · **Поверхня:** веб ·
**Залежності:** немає (`app/charts.py` ✅, `tests/test_mobile_layout.py` ✅)

## Проблема

Застосунок mobile-first (маніфест `display: standalone`, окремий тест розкладки на
390/320px), але **інтерактив графіків недоступний з телефона**. Обробник тултипа —
тільки `mousemove`:

- `app/templates/dashboard.html:131`
- `app/templates/activity.html:178`
- `app/templates/daily.html:84`
- `app/templates/detail.html:113`

На дотику не спрацьовує жоден із них: користувач бачить полілінію без жодного способу
дізнатися значення в точці. Тобто на головному пристрої найдорожча частина візуалізації
(HRV/сон/стрес/темп/пульс) — декоративна.

Друга половина проблеми — **чотири незалежні копії одного й того ж коду** (~25 рядків
кожна) з розбіжностями, які вже накопичились: у `activity.html` формат `pace`, у
`dashboard.html` — `f1`, кламп країв 28px проти 42px. Будь-яке виправлення треба робити
чотири рази, і воно вже де-не-де не зроблене.

## User story

Як користувач із телефона я хочу провести пальцем по графіку і бачити значення й дату
під пальцем — так само, як це працює мишею на десктопі.

## Обсяг

**Входить:**

1. **Один компонент у `app/static/app.js`** — ініціалізація по `document.querySelectorAll('.chart[data-pts]')`,
   формат зчитується з `data-fmt` (`f1` / `int` / `pace` / `hr`), решта — з `data-pts`.
   Чотири inline-`<script>` видаляються повністю.
2. **Pointer Events замість `mousemove`** — `pointerdown`/`pointermove`/`pointerup` +
   `pointercancel`, `setPointerCapture` на палець, щоб ведення не губилось поза межами
   картки. `touch-action: pan-y` на `.cwrap` — вертикальний скрол сторінки лишається
   живим, горизонтальний жест іде графіку.
3. **Тултип не ховається на `pointerup`** одразу, а живе до наступного тапу поза
   графіком (на телефоні `mouseleave` не існує, а миттєве зникнення = «нічого не
   сталося»).
4. **Клавіатура + a11y** — `.cwrap` отримує `tabindex="0"`, стрілки ←/→ пересувають
   курсор по точках, `aria-label` на SVG уже є і доповнюється поточним значенням через
   `aria-live="polite"` у тултипі.

**Не входить:** зум/пан графіка, друга вісь, бібліотека графіків (SVG рендериться
сервером у `app/charts.py` — це свідоме рішення, воно лишається).

## Acceptance criteria

- [ ] У жодному шаблоні немає inline-скрипта графіка — рівно одна реалізація в `app.js`
      (тест: grep по `app/templates/*.html` на `mousemove` дає 0 збігів).
- [ ] Емуляція дотику в headless Chromium (`tests/test_mobile_layout.py` уже піднімає
      браузер): `pointerdown`+`pointermove` по `.cwrap` робить `.tip` видимим і
      непорожнім — на `/dashboard` і на сторінці активності.
- [ ] Вертикальний скрол сторінки пальцем **по графіку** не блокується.
- [ ] Формати не загубились при злитті: `pace` показує `4:52/км`, `hr` — `152 уд`,
      `f1` — один десятковий (юніт-тест на функцію форматування, без браузера).
- [ ] `prefers-reduced-motion` і відсутність JS не ламають сторінку — графік лишається
      статичним SVG, як зараз.

## Ризики

- `touch-action` треба ставити саме на `.cwrap`, не на `body` — інакше зламається скрол
  усієї сторінки; AC про скрол ловить це.
- `setPointerCapture` на старому WebKit — фолбек на звичайні листенери, деградація
  плавна (тултип працює, поки палець у межах картки).
