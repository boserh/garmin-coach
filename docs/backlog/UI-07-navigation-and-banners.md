# UI-07 · Навігація для великого пальця + одна система банерів

**Тип:** сторі покращення (UI-аудит 2026-08-06) · **Оцінка:** S ·
**Пріоритет:** 🟠 high · **Поверхня:** веб · **Залежності:** UI-02 (спільний `<head>`/CSS)

## Проблема

**Навігація.** `_nav.html` — плаский ряд із 7 посилань (для адміна 10) + кнопка виходу, з
`flex-wrap`. На 390px він переноситься на 2–3 рядки й **зʼїдає верх кожної сторінки**, а
на 320px — ще більше. Пункти при цьому рівноправні: щоденні «Дашборд/Програма» стоять
поряд із «База даних»/«Кеші», які відкриваються раз на місяць. У standalone-режимі (а
маніфест просить саме його) верхня зона — найгірше місце для основної дії: до неї не
дотягується великий палець.

**Банери.** У `dashboard.html:33-73` — **пʼять** повідомлень (невалідні креди Garmin,
збої API, бекап, бюджет LLM, нема історії), кожне зі своїм інлайновим
`style="border-color:#f7768e;background:rgba(247,118,142,.08)"`. Кольори зашиті хексами
повз токени `--intervals`/`--tempo` з `app.css`, один і той самий «попереджувальний
жовтий» написаний руками в трьох місцях, а формула `rgba(...,.08)` — у чотирьох.
Аналогічні інлайнові банери повторені в `activity.html:20-28` (ще 8 штук). Додати новий
стан = скопіювати рядок і не забути хекс.

## User story

Як користувач із телефона я хочу дотягуватись до головних розділів великим пальцем і не
гортати три рядки меню на кожній сторінці; як розробник — додавати банер одним класом,
а не хексом.

## Обсяг

**Входить:**

1. **Нижня таб-панель на вузьких екранах** (`max-width: 36rem` — той самий брейкпоінт, що
   вже в CSS): 4–5 головних розділів (Дашборд · Програма · Інсайти/Мої дані · Чат ·
   Ще), `position: fixed; bottom: 0`, `padding-bottom: env(safe-area-inset-bottom)`.
   Верхній ряд на телефоні згортається у назву сторінки; на десктопі лишається поточна
   горизонтальна навігація без змін.
2. **«Ще» як `<details>`** — решта (Налаштування, Аналізи, Інфо) + адмінські пункти. Не
   випадне меню на JS: сайт свідомо працює без нього.
3. **Компонент банера в `app.css`** — `.banner` + модифікатори `.banner--info/--warn/
   --danger/--ok`, кольори через `color-mix(in srgb, var(--tempo) 8%, transparent)` (у
   `app.css` цей патерн уже застосований для `.checkup-results`). Жодного хекса в
   шаблонах.
4. **`_banners.html`** — один цикл по списку `banners`, який роутер збирає як
   `[{level, icon, text, link}]`. Дашбордні пʼять і активністні вісім переїжджають туди;
   логіка «показувати/ні» лишається в роутері, де вона й є.
5. **Активний пункт із `aria-current="page"`**, а не лише кольором.

**Не входить:** редизайн самих сторінок, перейменування розділів, JS-роутинг.

## Acceptance criteria

- [ ] На 390px і 320px висота навігації над контентом ≤ один рядок; таб-бар не перекриває
      контент (нижній `padding` у `body` враховує його висоту — це вже перевіряє
      мобільний guard, якщо йому додати перевірку перекриття).
- [ ] `grep 'style="border-color:#' app/templates/*.html` → 0 збігів.
- [ ] Кожен банер має `role="status"` (info/ok) або `role="alert"` (warn/danger).
- [ ] Таб-бар не показується на `/login`/`/register` (там немає куди йти).
- [ ] Клавіатурна навігація: усі пункти в табстопах, видимий фокус (зараз фокус-стиль є
      лише в інпутів).
- [ ] Мобільний guard проходить на всіх сторінках зі списку.
