# UI-04 · Чекін після тренування прямо у вебі (RPE / біль / нотатка)

**Тип:** сторі покращення (UI-аудит 2026-08-06) · **Оцінка:** S ·
**Пріоритет:** 🔴 highest · **Поверхня:** веб · **Залежності:** EP-12 ✅ (`/checkin` у боті),
NF-28 ✅ (`app/db/lifestyle.py`)

## Проблема

`ActivityRecord.subjective` (RPE + біль) — вхід для **половини аналітики**: EP-12-тренд,
NF-04-ризик (`injury._pain_signal`/`_rpe_signal`), NF-30-повернення після болю, адаптація
плану, ранковий звіт. Веб цей стовпчик **тільки читає**:

- `app/templates/activity.html:73-74` показує `a.rpe` і `a.pain`;
- `app/routers/me.py:339` віддає `rpe` у картки;
- **жодного `POST`, який його пише** — у `app/routers/*.py` немає ані форми чекіну,
  ані ендпоінта.

Записати можна виключно через Telegram (`/checkin`). Тобто користувач, який відкрив
дашборд одразу після пробіжки й бачить свіжу активність, мусить перемкнутись у месенджер
і згадати команду. Пропущений чекін — це не «менше даних у табличці», це деградація
радара травм і адаптації: вони мовчать, коли субʼєктивного входу нема.

## User story

Як користувач, який щойно синхронізував пробіжку, я хочу поставити RPE в один тап прямо на
картці активності (і, якщо треба, позначити біль) — не виходячи з веб-застосунку.

## Обсяг

**Входить:**

1. **`POST /me/activities/{id}/checkin`** — RPE 1–10, чекбокс болю + місце (той самий
   словник, що в боті — реюз, не друга копія), необовʼязкова нотатка. Пише в
   `ActivityRecord.subjective` тим самим шляхом, що бот, з тією ж валідацією.
2. **Віджет на `/me/activities/{id}`** — ряд із 10 пігулок RPE (тап = сабміт, без
   «зберегти»), під ним згорнута деталізація болю. Уже заповнений чекін показується як
   стан із можливістю змінити.
3. **Промпт на дашборді** — якщо остання активність за сьогодні/вчора без `subjective`,
   у блоці «Останні тренування» зʼявляється рядок «Як пройшло? RPE →» з тими ж пігулками
   інлайн. Один тап з головного екрана.
4. **Вечірній lifestyle-лог (NF-28) тим самим віджетом** — теги вже мають словник і CRUD
   (`app/db/lifestyle.py`), у вебі їх ввести теж ніяк. Той самий компонент пігулок,
   мультивибір.

**Не входить:** редагування чекінів заднім числом за довільну дату (є `/me` + ресинк),
довільні поля — набір лишається той самий, що в боті, інакше розʼїдуться два входи.

## Acceptance criteria

- [ ] Пігулка RPE пише `subjective.rpe` і зʼявляється в `injury.assess` наступного разу
      без жодних додаткових кроків (тест: чекін через веб → `_rpe_signal` бачить значення).
- [ ] Бот і веб пишуть **однаковою** структурою — тест порівнює dict після
      `/checkin`-шляху й після веб-POST (одна функція-запис на обох, не дві).
- [ ] Повторний чекін оновлює, не дублює; історія не множиться.
- [ ] Демо-акаунт не пише (той самий гард, що на регенерації розбору,
      `app/routers/me.py`).
- [ ] Працює без JS: пігулки — це `<button>` у формі, JS лише прибирає перезавантаження.
- [ ] Мобільна розкладка на 320px не ламається (10 пігулок переносяться, а не виїжджають).
