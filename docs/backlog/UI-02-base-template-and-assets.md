# UI-02 · `_base.html` + самохостинг шрифта (і поламаний CSS-guard мобільного тесту)

**Тип:** сторі покращення / борг (UI-аудит 2026-08-06) · **Оцінка:** S ·
**Пріоритет:** 🟠 high · **Поверхня:** веб · **Залежності:** немає

## Проблема

**26 шаблонів дослівно повторюють один `<head>`** — той самий `<meta viewport>`, ті самі
три теги Google Fonts, той самий `app.css?v=4`, той самий `app.js?v=1`, маніфест, іконки,
`theme-color`. Наслідки вже видно в коді, це не гіпотеза:

1. **Версія CSS бампається руками** — і вже розсинхронізована з тестом:
   `tests/test_mobile_layout.py:159` робить `r.text.replace("/static/app.css?v=3", "app.css")`,
   тоді як шаблони давно віддають `?v=4`. Заміна не спрацьовує → збережена сторінка тягне
   CSS з неіснуючого шляху → **guard мобільної розкладки міряє нестилізовану сторінку**.
   Тобто тест, який має ловити горизонтальний скрол, зараз тихо зелений ні на чому.
2. **`activity.html` має свій набір тегів** — `favicon.svg` замість `icon.svg`, без
   маніфеста, без `theme-color`; у standalone-режимі це помітно.
3. **Зовнішній Google Fonts** на застосунку, який живе на Pi у локальній мережі: перший
   рендер чекає сторонній CDN, а без інтернету сторінка малюється системним шрифтом
   (метрики різні → інша висота карток, ніж міряв тест). Плюс запит на сторонній хост із
   персонального health-застосунку — небажаний за замовчуванням.

## User story

Як розробник цього застосунку я хочу міняти `<head>` в одному місці, а як користувач —
щоб сторінка відкривалась однаково швидко й однаково виглядала без інтернету.

## Обсяг

**Входить:**

1. **`app/templates/_base.html`** — `{% block title %}`, `{% block head %}` (для
   сторінкових `<style>`), `{% block body %}`; усі 26 шаблонів переходять на `extends`.
   Сторінкові стилі, що вже де-факто спільні (`.thread`/`.turn` з чату, `.topnav` з
   `_nav.html`), переїжджають в `app.css`.
2. **Хеш замість ручної версії** — `?v={{ asset_v }}`, де `asset_v` рахується один раз на
   старті з mtime/розміру `app.css`+`app.js` і кладеться в глобали Jinja. Ручний бамп
   зникає як клас помилки.
3. **Inter — локально**, `app/static/fonts/` + `@font-face` з `font-display: swap`, лише
   потрібні накреслення (400/500/600/700, latin+cyrillic subset). Теги `preconnect`/
   `googleapis` прибираються.
4. **Полагодити `tests/test_mobile_layout.py`** — заміна CSS-шляху перестає залежати від
   рядка версії (regex по `/static/app.css\?v=\S*`), плюс `assert`, що заміна реально
   відбулась (інакше тест мовчки міряє нестилізоване).

**Не входить:** зміна самої дизайн-системи, темна/світла тема (окремо), build-крок/
бандлер — проєкт свідомо без фронтенд-тулінгу.

## Acceptance criteria

- [ ] Жоден шаблон, крім `_base.html`, не містить `<head>` (grep по `fonts.googleapis.com`
      → 0 збігів, по `<!doctype` → 1 файл).
- [ ] Мобільний guard падає, якщо CSS не під'їхав: у тесті є `assert` на факт підстановки,
      і він перевірений навмисним «зламом» під час рев'ю.
- [ ] Сторінка повністю рендериться з вимкненою мережею (лише `localhost`) — шрифт свій,
      жодного зовнішнього запиту (перевірка тим самим Playwright'ом: список запитів не
      містить сторонніх хостів).
- [ ] Після зміни `app.css` наступний запит сторінки віддає новий `?v=` без правок у
      шаблонах.
- [ ] Сторінка активності отримує маніфест/`theme-color`/ту саму іконку, що решта.
