# NF-34 · Відпустка з контекстом: тренер знає, що мене немає — і що я там робитиму

**Тип:** нова фіча (з живого спостереження власника, 2026-08-16) · **Оцінка:** S/M ·
**Пріоритет:** 🟠 high (тижневий підсумок зараз відверто бреше) · **Поверхня:** бот + веб ·
**Залежності:** EP-07 ✅ (дайджест), EP-18 ✅ (памʼять тренера), NF-03 ✅ (`/sick`),
NF-18 ✅ (авто-питання про хворобу)

## Проблема

Тижневий підсумок за тиждень відпустки прочитав нуль пробіжок як **провал**:

> 📊 Цього тижня жодної пробіжки (0 з 2 запланованих, compliance 0%)…
> 🎯 На треку до цілі — ні, відстаєш.

Ранковий звіт того ж дня при цьому про відпустку **знав** («вже після відпустки») — але
знав випадково: він читає вчорашній звіт і памʼять тренера, тож одна згадка протікала
вперед по одному дню. Дайджест не читає ні того, ні іншого.

У даних свідома пауза й зрив виглядають однаково — нуль. Відрізнити їх може лише сама
людина, отже вона має мати де це сказати **один раз** і так, щоб прочитали всі поверхні.

Друга половина проблеми — сам контекст. «Відпустка» ще нічого не пояснює: лежати на пляжі,
тиждень трекінгу і кайт-тиждень — це три різні навантаження (розтренування / тихий обсяг на
ногах / щоденна втома без бігу). Без цього тренер бачить «не бігав», а не «звісно не бігав,
він шість годин на день на кайті».

## User story

Як користувач я хочу оголосити період відсутності й написати своїми словами, що саме там
робитиму, — щоб тренер не соромив мене за пропущені сесії, пояснював тижневі цифри цим, і
не пропонував «наздогнати» обсяг після повернення.

## Обсяг

**Входить:**

1. **Модель `AwayPeriod`** (`user_id`, `start_date`, `end_date`, `kind`, `note`) + чисті
   правила `app/away.py` (парсинг дат, валідація, перетин із тижнем, промпт-блок).
   `kind`: `rest` / `active` / `sport` / `work` — закритий словник із рядком «чого чекати
   від тіла»; специфіка («кайт у Дахабі») — у вільному `note`.
2. **Три двері, один валідатор:** `/away 16.08-24.08 кайт` у боті (0 Claude), форма на
   `/me/profile`, і — найчастіший шлях — правка плану (`/plan <текст>`), де модель
   повертає додаткове поле `away`, що застосовується тим самим ✅, що й операції плану.
3. **Читають усі:** `away_db.build_context` → ранковий звіт, тижневий підсумок (з
   `days_in_week`), `/ask`, генерація плану, адаптація, `/sick`. Один `AWAY_BLOCK` у
   `prompts.py`.
4. **Тиша замість докорів:** авто-питання «схоже, ти захворів» (NF-18) не спрацьовує в
   оголошені дні.

**Не входить:** автоматичне визначення відпустки з даних (геолокація, розрив у синхронізації),
окрема «відпускна» перебудова плану — план і далі рухає звичайний `/plan`/`/sick`.

## Acceptance criteria

- [x] Оголошений період потрапляє в контекст **і** ранкового звіту, **і** дайджесту
- [x] Дайджест бачить, скільки днів ТОГО тижня припало на відсутність (`days_in_week`)
- [x] Промпт прямо забороняє «наздоганяти» обсяг після повернення
- [x] Період без дати кінця / довший за 120 днів не зберігається (інакше тренер замовкає назавжди)
- [x] Оголошення періоду не віддає закешований «довідпустковий» звіт (ключі дедуп-кешу)
- [x] `/plan`-пропозиція показує, що саме запише, ДО ✅; ❌ не лишає сліду
- [x] Користувач без жодного періоду отримує рівно ті самі промпти, що й до фічі
- [x] NF-18 мовчить під час оголошеної відсутності
