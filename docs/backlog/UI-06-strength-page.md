# UI-06 · Сила у вебі: e1RM по вправах, тоннаж, застої

**Тип:** нова фіча (UI-аудит 2026-08-06) · **Оцінка:** M ·
**Пріоритет:** 🟡 medium · **Поверхня:** веб · **Залежності:** NF-27 ✅
(`app/strengthstats.py`), EP-03 ✅ (прогресія силових)

## Проблема

`app/strengthstats.py` (NF-27) рахує повний набір: `session_tonnage`, `session_e1rm`
(Epley), `weekly_stats`, `e1rm_trend`, `detect_stalls`, `recent_lifts`. Grep по
`app/routers` + `app/templates` дає **нуль згадок** — все це існує тільки як контекст для
промпта і рядок у Telegram.

Що бачить користувач сьогодні у вебі: на сторінці активності — список назв вправ із
підходами (`activity.html:141-153`), на формі плану — прев'ю силового дня. **Прогресії
немає ніде**: неможливо відповісти на базове питання силового тренування — «мій присід за
три місяці виріс чи ні?» — хоча відповідь уже пораховано і викинуто.

Це асиметрія проти бігу: там є графіки, тренди аеробної ефективності, рекорди й
порівняння періодів. Силова — рівноправна половина плану (`type="strength"` у
`PlannedWorkout`, окремі дні в intake), а показана як плаский список.

## User story

Як користувач, що робить силові за планом, я хочу бачити криву e1RM по кожній вправі й
тижневий тоннаж — щоб розуміти, чи прогресую, і бачити застій до того, як він стане
місяцем змарнованих тренувань.

## Обсяг

**Входить:**

1. **`GET /strength`** — три блоки з наявних функцій:
   - **e1RM по вправі** — графік за тижнями (`e1rm_trend`), вибір вправи пігулками з
     `recent_lifts`; поруч поточний максимум і зміна за 4/12 тижнів;
   - **Тижневий тоннаж** — стовпчики (`weekly_stats`), з розбивкою за групами вправ;
   - **Застої** (`detect_stalls`) — картки «жим лежачи: 5 тижнів без росту» з посиланням
     на останні сесії з цією вправою.
2. **Блок сили на сторінці активності** — для силової сесії: тоннаж цієї сесії, e1RM по
   вправах і дельта проти попереднього разу (`session_tonnage`/`session_e1rm` — уже
   посесійні функції, саме для цього).
3. **Заміна плаского списку вправ** на наявний Garmin-подібний вигляд `.wblock`/`.wcard`
   (у CSS він **уже є** й використовується в плані) з фактичними кг×повтори.
4. **Мітка «e1RM — оцінка за Epley»** з розкриттям формули: показувати розрахунковий
   максимум як факт без пояснення — вводити в оману.

**Не входить:** ручне введення сетів (джерело — Garmin), нові формули оцінки максимуму
(Epley уже обрано в NF-27), рекомендації ваги на наступний раз (це EP-03 і воно вже
працює через план).
